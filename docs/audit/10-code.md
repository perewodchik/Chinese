# 10. Код: что рефакторить

## Итог

Около 108 000 строк TypeScript (из них игра 走走 и мини-игры — 39 000),
34 000 строк CSS, 173 файла тестов (1254 теста, все проходят),
`npm audit` чист. Архитектура сервера — ровная: порты и сервисы
(`server/src/application`), два хранилища за одним интерфейсом, маршруты
тонкие. Домен клиента (`src/domain`) — чистые функции с тестами. Слабое
место — **слой экранов**: большие компоненты, перекрёстные импорты между
фичами, две версии одного раздела, один CSS на всё, системные диалоги
браузера и отсутствие линтера. Ошибок, ломающих данные, при чтении не
найдено; найденные дефекты — в конце файла.

## Задачи

<a id="r1"></a>
### R1 (В) Линтер и форматтер в CI

Нет ни ESLint, ни Prettier/Biome; CI (`.github/workflows/check.yml`) гоняет
только сборку, тесты и `npm audit`. Поставить **Biome** (один инструмент,
быстрый) или ESLint + Prettier. Правила минимум: `react-hooks/rules-of-hooks`
и `exhaustive-deps`, запрет `any`, неиспользуемые импорты, запрет импорта
между фичами (R3) и из `src/world` в остальное. Форматирование — отдельным
коммитом на весь репозиторий, чтобы не мешалось с правками (предупредить
другие сессии: `CLAUDE.md` говорит, что несколько сессий работают в одном
дереве). `npm run lint` — в CI и в «definition of done»
(`docs/development-standards.md`).

### R2 (В) Одна версия Speak, раздел `pinyin` разобрать

(`NarratorsPage.tsx` — 669), курс звуков, история попыток, и общие части,
которые импортирует новая `src/features/speak/` (15 импортов `../pinyin/`).
Сделать после V9:

- удалить старые Phrases и флаг `speakV2` (`state.ts`, `migrations.ts`,
  `router.tsx` `SpeakRoute`, `SettingsPage.tsx`);

  (тоны и уроки), `features/voices/` (рассказчики → настройки, V11),
  общее (`RecordButton`, `useRecorder`, `ScoredLine`) → `src/ui/speech/`
  или `features/shared/speech/`;
- CSS: `pinyin.css` (2982) и `phrases.css` (1717) — удалить мёртвое после
  удаления экранов (проверка: `check-screens.mjs` до и после).

<a id="r3"></a>
### R3 (В) Границы между фичами

Правило из README › Layout проверить и закрепить линтером: фича
импортирует из `domain`, `store`, `ui`, `platform`, `api`, `navigation`,
`features/shared` — и **не** из другой фичи. Сейчас нарушают: `today` →
`cards`, `reader`, `auth` (`useContinue` экспортируется из страницы
`ReadPage.tsx`; `useCardsToday` — из `CardsPage.tsx`); `speak` → `pinyin`;
`reader` → `pinyin`; `AppLayout` → `library`, `words`, `settings`.
Хуки-селекторы (`useContinue`, `useCardsToday`, `useWordDone`,
`useWordLevel`) вынести из файлов страниц в `src/store/selectors/` или
`features/shared/`.

<a id="r5"></a>
### R5 (В) Маршруты: ленивые куски

`src/app/router.tsx` импортирует все страницы статически; только игра и
мини-игры загружаются по требованию. Итог — 2,5 МБ в первом файле для
экрана входа. Сделать `lazy` для: `videos`, `collections` (PDF:
`pdf-lib` и шрифты), `speak`/`talk`/`sounds`, `stats`, `admin`, `account`,
`settings`. Read, текст, Cards — в основном куске. Место под страницу при
загрузке куска — тот же каркас (без сдвига вёрстки; `Splash` уже есть).
Цель: первый файл < 1 МБ до сжатия.

<a id="r6"></a>
### R6 (С) Системные диалоги → свои

18 вызовов `prompt()` / `confirm()`: новая книга, переименование, «на какую
полку» (текстом через запятую), удаление, сброс сессии
(`ReadPage.tsx:108, 187, 393, 399, 402`, и др.). В Safari на iOS они
выглядят чужими, блокируют страницу, а в установленном на экран «Домой»
приложении `prompt` ненадёжен. Сделать два компонента на базе
`src/ui/Modal.tsx`: `useConfirm()` (текст, опасное действие, ввод слова для
необратимого) и `usePromptSheet()` (одно поле или выбор из списка). Заменить
все 18.

<a id="r8"></a>
### R8 (С) Рабочее место одним документом

Всё состояние ученика — один JSON до 16 МБ, сохраняемый целиком при каждом
изменении (`src/store/sync/`, `PUT /api/workspace`). На Vercel тело
ограничено 4,5 МБ (S18 — открыт). С картинками комиксов и сотнями текстов
предел близко. Путь:

1. измерить: размер по разделам документа у реального аккаунта (тексты,
   `book`, `activity`, видео) — скрипт в `scripts/`;
2. вынести самое тяжёлое из документа в свои таблицы с собственными
   маршрутами: сначала **тексты** (`texts(user_id, id, set_id, document)`;
   каталог T1 даёт для этого образец), затем попытки и видео;
3. в документе остаются настройки, наборы, расписание карточек — то, что
   меняется часто и весит мало;
4. позже — сохранение изменениями (patch), а не целиком.

Большая работа; делать после каталога и до роста числа учеников.

### R9 (С) CSS

`src/styles.css` — 6139 строк в одном файле, загружается всем; у фич свои
файлы, но стили экранов местами лежат в общем. Сделать: в `styles.css`
остаются токены, сброс, «части страницы» и компоненты `src/ui`; стили
экранов — в файл фичи, импортируемый её компонентом (так они попадут в её
ленивый кусок, R5). Инлайновые `style={{…}}` (384): раскладку — в классы,
оставить только динамические значения (`--fill`, ширина). Мёртвые классы —
найти инструментом (purgecss в режиме отчёта), удалять по фиче со снимками.

<a id="r11"></a>
### R11 (С) Тесты: скорость и экраны

- `npm test` идёт ~8,5 минуты одним процессом. Разделить на `test:unit`
  (домен, быстрые) и `test:server` (база, pglite), включить параллельность
  по файлам (`--test-concurrency`), найти самые медленные (`--test-reporter`
  с длительностями) — вероятно, pglite и сборка игры. Цель: < 2 минут для
  того, что запускают перед каждым коммитом.
- Тестов экранов нет. Не вводить библиотеку компонентов ради покрытия;
  вместо этого — 5–6 сценариев Playwright на главные пути (регистрация →
  первый текст → слово → карточка; добавить текст; сказать фразу; настройки;
  админ: приглашение), на локальной базе, в CI. Основа — `scripts/
  fresh-user-probe.mjs` и `check-screens.mjs` (N9).

<a id="r14"></a>
### R14 (С) Комментарии и документация

Комментарии в коде — длинные рассказы о том, как было раньше («It used to
be a plan of four or five steps…»). Историю хранит git. Правило: комментарий
говорит, **почему так сейчас**, в одну-три строки; история — в сообщение
коммита или `docs/`. Чистить по ходу правок, не отдельной кампанией.
`README.md` описывает сайт как инструмент для печатных листов и запуск на
Windows (`start.cmd`), а `CLAUDE.md` — Mac; привести к тому, чем сайт стал.
`docs/public-launch-plan.md` и этот аудит — после выполнения свести в один
короткий `docs/backlog.md`.

<a id="r15"></a>
### R15 (С) Ошибки, которые глотаются

24 места `.catch(() => undefined)` и 161 `catch` — многие оправданы
(«не удалось — не страшно»), но ошибки сети в платных действиях и
сохранении должны доходить до человека. Пройти список; для каждого:
оставить с комментарием «почему можно», либо показать тост, либо записать
(на сервере — `log`). Клиентские ошибки собирать: `window.onerror` →
`POST /api/activity/event { kind: 'error', message }` (A7) с лимитом —
сейчас о сломанном экране у ученика владелец не узнает.

<a id="r17"></a>
### R17 (Н) Собранный файл в репозитории

`api/index.js` (183 КБ) — результат сборки, лежит в git и должен
пересобираться и коммититься при каждой правке сервера (в истории есть
коммит «bundle rebuilt… e9ce1a7 changed the server and not the bundle
beside it»). `vercel-build` и так собирает его на Vercel. Проверить, нужен
ли он в репозитории (нужен, только если Vercel находит функции до сборки);
если нужен — тест в CI «собранный файл соответствует исходникам», если нет
— в `.gitignore`.
