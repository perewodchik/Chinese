# 7. Добавление текстов через сайт

[← к плану](README.md) · заменяет и продолжает `docs/photo-to-text.md`.

## Что сейчас

| Способ | Кто может | Шаги |
|---|---|---|
| Скилл `/add-text` в Claude Code (фото или текст → всё само) | только владелец: нужен Claude Code, репозиторий и пароль аккаунта | 1: отправить фото |
| «Write texts with Claude» (`/texts/session`) | любой, у кого есть свой чат Claude | форма → копировать промпт → вставить в Claude → копировать ответ → вставить |
| «New book» | любой | создаёт пустую полку, которую нечем заполнить |
| Свой текст в Speak › Voices («Your own texts») | у кого есть ключ MiniMax | вставить текст → рассказчик читает |

У ученика **нет способа положить на полку свой китайский текст** (из
учебника, из чата, с фото), если у него нет подписки Claude. А у владельца
лучший способ живёт вне сайта.

## Ограничения, которые задал владелец

- Всё через интерфейс сайта, для ученика и для админа.
- Не сложнее, чем сейчас у владельца: фото → готово.
- Платный API — нежелателен.

## Решение коротко

Три слоя, каждый полезен сам по себе:

1. **Каталог** (T1): админ публикует готовые книги, ученик берёт в один тап.
   Большинству учеников ничего добавлять не придётся.
2. **Мгновенный черновик без ИИ** (T2, T3): вставил или отсканировал
   китайский текст — через секунду он на полке: разбит на предложения и
   слова, с пиньинем и значениями слов из словаря сайта, со счётом «сколько
   ты знаешь». Этого достаточно, чтобы читать, слушать и учить слова.
3. **Дополнение** — перевод предложений, грамматика, вопросы, упрощённый
   пересказ — приходит потом одним из трёх путей: свой чат Claude (T4,
   бесплатно), очередь к Claude Code владельца (T5, для админа и по его
   желанию — для учеников), платно за кредиты (T10, если владелец решит).

Фото без API: **iPhone и iPad сами читают текст с камеры.** В любом поле
ввода в Safari есть «Scan Text» (значок в меню вставки; iOS 15+): камера
наводится на страницу, и текст вставляется в поле. То же — долгое нажатие на
текст в фотографии → Copy. Сайту не нужно ни принимать фото, ни
распознавать его.

## Задачи

<a id="t1"></a>
### T1 (К) Общий каталог текстов

**Сделано (2026-11-11), частично.** Таблицы `catalog_books`,
`catalog_texts`, `catalog_pictures` в обеих базах. `GET /api/catalog`,
`GET /api/catalog/:id` (вошедшим; скрытые — только админу);
`GET/POST /api/admin/catalog`, `PUT /api/admin/catalog/:id` (новая версия),
`PATCH … { hidden }` — роль админа, второй шаг, свежий пароль, журнал
(`catalog-published/updated/hidden/shown`). Тексты проходят схему
(`server/src/application/catalog-schema.ts`): известные поля с пределами,
прогресс и посторонние поля отброшены, в историях и сценах — без адресов.
Картинки текстов копируются из аккаунта админа в каталог;
`GET /api/pictures/:key` отдаёт их любому вошедшему. Лицензия — только из
списка «written for this site / public domain / CC…». Клиент: в меню книги
у админа «Publish to the library…» / «Publish a new version…»; в Read —
блок «From the library» с книгами, которых у ученика нет, **Add** кладёт
копию книги на новую полку (`TextSet.catalog = { id, version }`, с загрузкой
и слиянием) и открывает её. Тесты: `server/test/catalog.test.ts`,
`postgres.test.ts`, `src/store/*.test.ts`.

**Осталось.** (1) Тексты взятой книги — по ссылке из каталога с кэшем на
устройстве, а в рабочем месте только прогресс; (2) тихо подтягивать новую
версию; (3) публикация токеном `catalog:write` (сейчас маршруты требуют
свежего пароля, а у токена его нет). (1) меняет то, как читалка, карточки
и статистика берут тексты, — отдельный большой шаг.


**Сервер.**
- Таблицы: `catalog_books(id, title, title_zh, level, kind, cover, blurb,
  source, licence, published_at, published_by, version, hidden_at)`,
  `catalog_texts(id, book_id, position, document jsonb, chars int)`,
  `catalog_pictures(key, mime, bytes)`, позже `catalog_narrations` (K14).
- `GET /api/catalog` — список книг (любой вошедший; кэш `private, max-age`),
  `GET /api/catalog/:bookId` — книга с текстами.
- `POST /api/admin/catalog` — опубликовать: тело = полка из рабочего места
  админа (тексты как `GeneratedText`), **проверенное схемой zod на сервере**
  (SEC12): длины, число строк, поля. `PATCH` — скрыть, обновить версию.
  Только роль `admin` (A1), с журналом (A2).

**Клиент.**
- В Read — блок **From the library** (книги каталога, которых у ученика
  нет): обложка, уровень, «comfortable / a stretch» (V4), кнопка **Add**.
- Взятая книга — полка в рабочем месте со ссылкой `catalogId` и версией;
  тексты читаются из каталога и кэшируются на устройстве (IndexedDB), а в
  рабочем месте лежит только прогресс. Обновилась версия — тихо подтянуть.
- У админа на странице полки (`ShelfPage`, меню «⋯») — **Publish to the
  library…**: уровень, описание, источник и лицензия (обязательные поля).

**Авторские права (L2 старого плана).** В каталог — только то, что написано
для сайта (скилл `/story`, сессии Claude) или свободно. Страницы настоящих
книг и манга остаются в личном рабочем месте. Поле `licence` обязательно,
форма публикации говорит об этом прямо.

**Готово, когда.** Админ публикует полку; новый аккаунт видит её в Read и
читает; изменение рабочего места админа после публикации каталог не меняет.

<a id="t2"></a>
### T2 (В) Лист «Add a text»

Одна точка входа: кнопка **Add a text** в Read (V3) и на странице книги.
Лист (на телефоне — снизу, на iPad — по центру):

```
Add a text
┌──────────────────────────────────────────────┐
│ Paste or type Chinese here…                  │
│                                              │
│ (на iPhone: tap here, then “Scan Text” to    │
│  read it off a page with the camera)         │
└──────────────────────────────────────────────┘
Title (optional)          Goes into: [Evening ▾] [New book]
[ Add it ]                              ← основная кнопка

Other ways:  From the library ›   Have Claude write texts ›
```

- Поле принимает вставку любого размера до предела (например, 3000
  иероглифов на текст; больше — предложить разбить на главы по пустым
  строкам).
- Не-китайское (латиница, цифры) допускается; если иероглифов нет совсем —
  подсказка на месте.
- Традиционные → упрощённые: предупредить, если текст традиционный
  (переключатель уже есть на чтении).
- «Add it» сразу создаёт текст (T3) и открывает его. Никаких шагов между.
- Черновик поля хранится (sessionStorage по аккаунту), пока не добавлен.

**Фото как вложение** — только для админа и только вместе с T5 (очередь):
в листе появляется «Send photos to be read». Для остальных — «Scan Text».

**С чего начать.** `src/features/reader/` — новый `AddTextSheet.tsx`;
существующие куски: `addTexts` (`src/store/commands.ts`), `sentencesOf` и
построение текста из своего текста в `src/domain/ownText.ts` (уже делает
`GeneratedText` для Voices — основа для T3).

<a id="t3"></a>
### T3 (В) Мгновенный черновик без ИИ

Всё нужное уже есть в клиенте:

| Что | Чем |
|---|---|
| предложения | `sentencesOf` (`src/domain/ownText.ts`) |
| слова | `segment` (`src/domain/segment.ts`) — 10 000 слов HSK + слова иероглифов |
| пиньинь | `pinyinOf` (там же) |
| значения слов | `lib.byWord`, `lib.byChar` (`public/data/words.json`, `characters.json`) |
| новые иероглифы и слова, «знаешь N%» | `toText`, `coverageOf` (`src/domain/parse.ts`, `text.ts`) |

Чего нет без ИИ: перевод предложений, грамматика, вопросы, упрощённый
пересказ, картинки. Текст-черновик помечается `draft: true`; на его
странице вместо перевода — тихая строка «No translation yet → Add
explanations» (ведёт к T4/T5/T10). Вкладки Words, Listen, Copy out, Say
работают сразу; Questions и Grammar скрыты, пока пусты.

Слабые места, которые надо назвать на экране, а не прятать:
- **Слова вне списков HSK** (имена, редкие слова) распадутся на иероглифы,
  и пиньинь многозначных иероглифов может быть не тот (行, 长, 了). Дать
  правку на месте: тап по слову → «Fix reading / Join with next / Split».
  Правки хранятся в тексте (`vocab`), как это делает автор в JSON.
- Расширить словарь: подключить полный CC-CEDICT (лицензия CC BY-SA уже
  учтена в `sources.html`) отдельным файлом, загружаемым по требованию
  (~10 МБ сжатого — только при добавлении текста, кэш на устройстве).
  Отдельная задача после первой версии.

**Готово, когда.** Вставленный абзац из 200 иероглифов открывается как
текст меньше чем за секунду, без сети; тап по слову открывает карточку
слова; слово добавляется в карточки.

<a id="t4"></a>
### T4 (С) Дополнение через свой чат Claude

То, что уже умеет сессия (`PromptStep` → `ImportStep`), для одного текста:

1. На черновике — **Add explanations › With your own Claude (free)**.
2. Сайт собирает промпт: китайский текст + что ученик знает + формат
   ответа (тот же JSON, что у скилла, раздел 3 `SKILL.md`) + «не меняй
   китайский текст». Кнопка **Copy and open Claude**.
3. Ученик вставляет в чат (к фото можно приложить само фото — тогда Claude
   заодно сверит распознанный текст), копирует ответ, возвращается, **Paste
   the answer**. Парсер тот же (`parseResponse`), и он сверяет, что
   китайские строки совпали с черновиком; расхождения показывает.

Три тапа и две вставки. Инструкция — K21.

<a id="t5"></a>
### T5 (С) Очередь к Claude Code владельца («фото → готово» на сайте)

Это вариант 1 из `docs/photo-to-text.md`; читать его целиком перед работой.
Суть: сайт кладёт фото или черновик в таблицу `inbox`, запускает сохранённую
процедуру Claude Code владельца (routine с API-триггером, на подписке, не на
платном API), та выполняет скилл и возвращает результат на сайт.

Изменения к тому плану:
- Процедура ходит на сайт **с токеном** (`SEC2`, область `inbox`), а не с
  паролем админа.
- Одна процедура обрабатывает всю очередь за запуск (у процедур есть
  дневной предел запусков).
- Кому доступно — решает админ: себе всегда; ученикам — флаг в `/admin`
  (A9) и/или за кредиты. По умолчанию — только админ.
- Фото уменьшается в браузере (1600 px, JPEG 0.8), хранится до готовности
  и не дольше 7 дней; счёт места — в квоту (S4).
- На полке — строка «Being read… usually 2 to 4 minutes», можно уйти.
- Процедура экспериментальная: модуль вызова отдельный, с тестом на
  записанном ответе; при отказе — честное сообщение и T4 как запасной путь.

Для владельца это и есть «не сложнее, чем сейчас»: открыл сайт на телефоне,
**Add a text › Send photos**, выбрал полку — дальше как скилл.

<a id="t6"></a>
### T6 (С) Проверка текста на сервере

Пока тексты лежат в рабочем месте владельца — проверять нечего. Но каталог
(T1), очередь (T5) и платное дополнение (T10) принимают текст на сервере:
одна схема zod `shared/text.ts` для `GeneratedText` (длины строк, не больше
N строк, допустимые поля, картинки только по своим ключам), один и тот же
разбор на клиенте и сервере. Сейчас формат описан только в
`src/domain/parse.ts` и в `SKILL.md`.

<a id="t7"></a>
### T7 (С) Правка добавленного текста

Сейчас текст нельзя поправить на сайте (опечатка распознавания, не то
чтение). Нужны: правка строки (китайский, пиньинь, перевод), объединить /
разделить предложения, удалить текст, переставить тексты в книге. Меню «⋯»
на странице текста → **Edit text**.

<a id="t8"></a>
### T8 (С) «Сколько это по силам» до добавления

Скилл показывает сводку трудности и предлагает пересказ попроще. В листе
T2 после вставки (до «Add it») — одна строка: «About 180 characters · you
know 64% · 22 new words — a stretch». Упрощённый пересказ — только через
T4/T5/T10 (его пишет ИИ).

<a id="t9"></a>
### T9 (Н) Импорт и экспорт файла

`ShelfPage` уже умеет «Export JSON». Добавить обратное: **Import a book
file** (тот же JSON) — способ поделиться книгой между учениками без
каталога и запасной путь, когда Claude ответил файлом.

<a id="t10"></a>
### T10 (Н) (владелец решает) Платное дополнение за кредиты

Единственный путь, где ученик нажимает одну кнопку и ничего не копирует, —
вызов модели с сервера. Владелец против платного API как основы; как
**необязательная платная функция** он укладывается в кредиты (M4): страница
текста стоит порядка центов на недорогой модели, и ученик платит за неё
сам. Не делать до этапа 7; до тех пор T4 и T5 закрывают потребность.
Если делать — цены и модель проверять по документации в момент работы,
ключ только в переменных окружения, лимиты и списание через K13.

## Порядок

T1 → T2 + T3 (вместе) → T8 → T4 → T7 → T6 → T5 → T9 → T10.
`docs/photo-to-text.md` после T5 пометить «заменено этим файлом» или
удалить.
