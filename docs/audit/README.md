# Аудит сайта и карта улучшений

Аудит от 2026-11-11 (коммит `572f643`). Вопрос аудита: что увидит человек,
который только что зарегистрировался, ничего не знает о том, как сайт сделан,
и хочет учить по нему китайский — и что нужно, чтобы сайт можно было открыть
другим людям, брать за него деньги и управлять им из админки.

Это продолжение `docs/public-launch-plan.md` (аудит от 2026-11-04). Там — то,
что уже сделано и что осталось по открытию сайта; здесь — новые находки и
решения. Где пункт продолжает старый, стоит его старый номер (например,
«см. P7»), дублировать его не надо: сделал — отметь в обоих файлах.

## Как смотрели

- Новый аккаунт на пустой базе (`HANZI_DB=.data/fresh.db`), без ключей и без
  Claude: `scripts/fresh-user-probe.mjs` и полноразмерные снимки каждого
  экрана на 375 px.
- Второй аккаунт с двумя текстами (добавлены через `npm run texts -- add`),
  чтобы увидеть экраны с содержимым.
- Сервер: прочитаны все маршруты `server/src/http/routes/`, сервисы входа,
  хранение ключей, конфигурация Vercel; на локальном сервере проверены
  обращение к админке чужим аккаунтом, запросы с чужого сайта, большие тела
  запросов, перебор пароля, похожие имена.
- `npm test`, `npm audit --omit=dev` (уязвимостей в зависимостях нет).

Боевой сайт и боевая база не трогались.

## Правила для агента

1. Одна задача за раз, в порядке плана ниже. Перед работой — `CLAUDE.md`,
   `docs/making-changes.md`, `docs/guidelines.md`; для экрана — скилл
   `hanzi-design`.
2. В каждом пункте есть: **что не так** (с файлом и строкой), **что сделать**,
   **с чего начать**, **готово, когда**. Если код с тех пор изменился и
   строка не совпадает — ищи по имени компонента или функции.
3. Проверка: `npm test`, `npm run vercel-build`, для экрана —
   `node scripts/check-screens.mjs` на 375, 768, 1024, светлая и тёмная тема,
   и WebKit. Сервер — только с `HANZI_DB=.data/<имя>.db`.
4. Сделал — поставь `[x]` здесь и в файле раздела, допиши строку в «Журнал».
   Сделал часть — оставь `[ ]` и допиши `— частично: …`.
5. **(владелец)** — решение или действие человека: агент не делает сам, а
   готовит варианты и напоминает.
6. Важность: **К** — критично, **В** — высокая, **С** — средняя, **Н** —
   низкая.

## Главное в десяти строках

1. **Пароль админа боевого сайта лежал в репозитории** (в скилле
   `add-text`). Владелец сменил его 2026-11-11, из файлов он убран; скилл
   читает `HANZI_PASSWORD` из окружения. Остались проверки из
   [SEC1](06-security.md#sec1) и токен вместо пароля (SEC2).
2. **Новому пользователю нечего читать.** Read пуст, а единственный путь —
   «Write the first texts» — открывает форму на три экрана, кнопка в конце
   которой выключена, пока в Библиотеке не отмечены выученные иероглифы. →
   [N1–N4](01-new-user.md).
3. **Самое нужное спрятано.** Карточки — ежедневное занятие — лежат в More;
   «Tell it what you know already» — последняя строка на странице карточек;
   добавление текста — значок «+» без подписи. → [V1](02-navigation.md#v1),
   [N3](01-new-user.md#n3).
4. **Today ничего не решает**: две ссылки, которые есть и в других местах, и
   полоска из семи пустых клеток. → [V2](02-navigation.md#v2).
5. **Speak — четыре вкладки с разной природой**: упражнение, настройка
   голосов с ключом, разговор, который у большинства скрыт, и курс звуков. →
   [V9–V13](02-navigation.md#speak).
6. **Настройки и профиль перемешаны**: ключи в настройках, расход ключей и
   устройства в профиле, одна лента из восьми карточек. →
   [03-settings-profile.md](03-settings-profile.md).
7. **Прогресс для нового или вернувшегося — нули и плоские линии.** →
   [G1–G8](04-library-progress.md#progress).
8. **Тексты добавляет только админ и только скиллом.** Можно без API:
   вставка или «Scan Text» на iPhone + мгновенный черновик из словаря сайта;
   общий каталог текстов от админа. → [07-adding-texts.md](07-adding-texts.md).
9. **Монетизация: кредиты, не реклама.** Расходы сайта переменные (озвучка,
   оценка произношения), поэтому бесплатная основа + пробный запас кредитов +
   пакеты; свой ключ остаётся бесплатной альтернативой. →
   [08-monetization.md](08-monetization.md).
10. **Админ определяется по имени из переменной окружения.** Нужны роли в
    базе по id аккаунта, журнал действий админа, блокировка, выдача
    кредитов. → [09-admin.md](09-admin.md).

### Этап 2 — новый пользователь доходит до первого текста

- [ ] **T1 (К)** Общий каталог текстов: админ публикует полку, ученик берёт. [→](07-adding-texts.md#t1)
  — частично: сервер (книги, тексты, картинки, схема, публикация/версия/скрытие, журнал), «Publish to the library…» у админа и «From the library» в Read сделаны; книга при добавлении **копируется** в рабочее место. Осталось: тексты по ссылке из каталога с кэшем на устройстве и тихим обновлением версии; публикация токеном `catalog:write`.
  **Вопрос владельцу:** взятая книга — копия в рабочем месте (сделано: просто, но книга из 10 текстов занимает ~50–100 КБ из 16 МБ) или ссылка на каталог с кэшем на устройстве (как в плане: экономит место, но меняет формат рабочего места и то, как читалка, карточки и статистика берут тексты)? Рекомендация: оставить копию, пока рабочие места не подходят к пределу; вернуться вместе с K14. От ответа зависят N1 и N2.
