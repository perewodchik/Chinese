# 5. Ключи, сценарий без ключей, озвучка

[← к плану](README.md) · продолжает фазу 6 из `docs/public-launch-plan.md`
(K1–K12). Номера здесь начинаются с K13.

## Что от чего зависит сейчас

| Функция | Сервис | Чей ключ | Без ключа |
|---|---|---|---|
| Оценка произношения (Speak, упражнения) | SpeechSuper | ученика | запись и «Mine» работают, оценки нет (K1 сделан) |
| Образец фразы в Speak | MiniMax (рассказчик) | ученика | голос устройства с пометкой (K2 сделан) |
| Чтение текста целиком (Listen), рассказчики | MiniMax | ученика | форма ключа (K6 не сделан) |
| Слова: запись носителя | файлы `public/voices/` | — | работает |
| Тексты, списки слов, проверка ответа | Claude | копировать/вставить | работает, без инструкции (K7) |
| Разговор, Ask | Claude CLI владельца | — | скрыто |
| Картинки к текстам | Gemini, только из скрипта | владельца | нет |

Проверенные факты из старого плана (K3, 5 ноября 2026): у **SpeechSuper нет
самостоятельной регистрации** — ключ по заявке с рабочей почты, затем
$0.006 за предложение и минимум $20 в месяц; у MiniMax — $60–100 за миллион
символов, дизайн голоса $3. Вывод: **обычный ученик свой ключ SpeechSuper
не получит никогда**, а MiniMax — только самый упорный. «Свой ключ» как
единственный путь к оценке и озвучке закрывает их почти для всех.

## Проблемы

1. Ключи вводятся в трёх местах: Settings (SpeechSuper), Speak › Voices
   (MiniMax), а расход показан в Account.
2. Первое, что видит человек в Settings и в Voices, — форма ключа.
3. Нет среднего пути между «ничего» и «свой ключ».
4. Озвучка привязана к рассказчику, которого надо сначала **создать**
   (описание голоса → пробы → сохранить) — это настройка для владельца, а не
   для ученика, который хочет нажать «слушать».
5. Одна и та же озвучка одного и того же текста у двух учеников делается и
   оплачивается дважды (ключ `text_narrations` включает пользователя).
6. Ошибка ключа (кончился баланс) показывается при каждой попытке (K5).
7. iFlytek стоит в интерфейсе равным выбором, хотя в старом плане записано
   «на сайте не используется».

## Задачи

<a id="k13"></a>
### K13 (В) Три уровня доступа — одна функция на сервере

Для каждой платной функции сервер решает, чем платить, в одном месте:

```
1. свой ключ ученика есть и не сломан  → им (кредиты не тратятся)
2. иначе у ученика есть кредиты          → ключом сайта, списать кредиты (M4)
3. иначе                                  → отказ с кодом `needs_credits`
админ (A1)                               → ключом сайта, без списания
```

Сейчас выбор ключа размазан: `speech-eval-service.ts` (`evaluate`) и
`narration-service.ts` читают `secrets` сами. Сделать
`server/src/application/paid-access.ts`:
`resolve(userId, service) → { via: 'own' | 'site', key, charge(units) }`.
Ключи сайта — в переменных окружения Vercel (`HANZI_SITE_SPEECHSUPER_*`,
`HANZI_SITE_MINIMAX_KEY`), никогда в базе и никогда клиенту.

Клиент получает статус одной ручкой (расширить `GET /api/account/usage`):
для каждого сервиса `via` и остаток. Компонент `NeedsKey` превращается в
`PaidAction`: показывает «Score it» / «Score it · 1 credit» / «Out of
credits → Get more or add your own key».

**Готово, когда.** Ученик без ключей с пробным запасом (M3) нажимает
«оценить» и получает оценку; тесты на все четыре ветки.

<a id="k14"></a>
### K14 (В) Готовая озвучка текстов каталога — одна на всех

Тексты каталога (T1) админ озвучивает **один раз** своим ключом; запись
хранится при тексте каталога (`catalog_narrations(catalog_text_id, voice,
mp3, timings)`) и отдаётся всем бесплатно, с кэшем на год. Это решает
главный вопрос «что озвучивать»: то, что читают все.

Тогда новый ученик без ключей и кредитов слушает стартовые тексты голосом
носителя/рассказчика, а не голосом устройства.

**С чего начать.** `narration-service.ts` (`text`, `audio`),
`postgres/text-narration-repository.ts`; ключ записи сейчас включает
пользователя — для каталога он от пользователя не зависит.

<a id="k15"></a>
### K15 (В) Свои тексты: озвучка по нажатию, не при создании

Рекомендация по вопросу «сразу ли озвучивать тексты»: **нет**.

- Текст добавился → звука нет, кнопка **Listen** есть.
- Первое нажатие: если есть свой ключ — озвучить; если кредиты — показать
  цену до запуска: «Read this text aloud: 320 characters · 3 credits.
  Kept for good» → **Read it**. Без кредитов и ключа — голос устройства с
  пометкой «device voice» и строкой «Natural voice · 3 credits».
- Первая строка текста — бесплатно и сразу (проба голоса), чтобы человек
  услышал разницу до оплаты.
- Озвучено один раз — хранится навсегда (уже так), повторное слушание
  бесплатно.

Почему не сразу: большинство добавленных текстов читают глазами один раз;
озвучивать всё — платить за то, что не слушают. У MiniMax цена за символ,
глава ≈ несколько центов (так написано в форме ключа) — на сотне учеников
это уже заметно.

<a id="k16"></a>
### K16 (С) Голоса без создания голоса

Ученику не нужно «делать рассказчика». Сделать 3–4 **готовых голоса сайта**
(женский, мужской, медленный учительский, детский для сказок) — владелец
создаёт их один раз (дизайн голоса $3 каждый), id лежат в конфигурации
сайта (`site_settings`, A11). Ученик выбирает из списка с кнопкой
прослушивания (пробы — готовые MP3 в `public/audio/samples/`, K6).

Создание собственного голоса по описанию остаётся только для тех, у кого
свой ключ MiniMax, — в `Settings › Voices`, за «Make your own voice».

Какой голос читает какой текст: по умолчанию — голос ученика из настроек;
для книги можно задать свой (поле у полки). Для каталога — голос, которым
озвучил админ.

<a id="k17"></a>
### K17 (С) Что озвучивается чем — одна таблица в коде

Сейчас источников звука несколько (`src/features/speak/modelVoice.ts`,
`src/features/reader/readAloud.ts`, `narratedClips.ts`, `src/ui/Say.tsx`,
`src/platform/speech.ts`). Правило одно, записать в
`src/platform/audio/sources.ts` и использовать везде:

| Что | 1-й источник | 2-й | 3-й |
|---|---|---|---|
| Слово | запись носителя из `public/voices` | вырезка из озвученного текста | голос устройства (с пометкой) |
| Строка текста | вырезка из озвучки текста | отдельная озвучка строки (кредит) | голос устройства |
| Весь текст | озвучка (каталог / своя) | — | голос устройства по строкам |
| Слог, тон (курс звуков) | запись носителя | — | **ничего** — устройству тоны не доверять |

Пометка «device voice» обязательна там, где учат произношению (правило из
`CLAUDE.md`: «Native recordings for anything that teaches pronunciation»).

<a id="k18"></a>
### K18 (С) Сломанный ключ (это K5)

Сервер помечает ключ (`broken_at`, причина: не принят / нет баланса) при
первом таком ответе поставщика, больше с ним не ходит, статус отдаёт
клиенту. В интерфейсе — та же строка `PaidAction`: «Your MiniMax balance
ran out → Top it up / Use credits instead». Сброс пометки — при сохранении
ключа заново или по кнопке «Try again».

<a id="k19"></a>
### K19 (С) Свой потолок расхода (это Q6)

Для своих ключей — необязательный предел в день («not more than 200
phrases»), для кредитов — подтверждение дорогих действий (> 10 кредитов за
раз). Проверка на сервере перед вызовом.

<a id="k20"></a>
### K20 (С) Оценка без SpeechSuper

Раз свой ключ SpeechSuper ученику недоступен, а кредиты могут кончиться,
нужен бесплатный минимум, который учит:

- **Слушай — скажи — сравни**: образец, своя запись, обе волны и обе
  высоты тона рядом (в README заявлено «Your tones, drawn… Nothing leaves
  the device» — проверить, что жив код рисования тона после перехода на
  SpeechSuper: `src/features/pinyin/voice.ts`; `/speaking/voice` сейчас
  переадресует на тоны с пометкой «gone»).
- **Распознавание браузера** (`SpeechRecognition` в Safari): «сайт услышал:
  …» — совпало или нет, без оценки слогов. Уже есть сообщения
  `RECOGNITION_MESSAGE`; проверить на iPhone.

Это не замена оценке, а то, что остаётся бесплатно всегда.

<a id="k21"></a>
### K21 (С) Инструкция «Claude без ключа» (это K7)

На шаге «Prompt» (`src/features/reader/PromptStep.tsx`,
`collections/build/ListPromptStep.tsx`): три пронумерованные строки и
кнопка «Open Claude» (уже есть ссылка `CLAUDE`). После вставки ответа —
понятная ошибка, если вставлено не то (обрезанный JSON, текст вместо JSON):
что именно скопировать. Сейчас парсер (`src/domain/parse.ts`) чинит многое
сам — проверить сообщения для трёх типичных ошибок.

<a id="k22"></a>
### K22 (Н) iFlytek и Azure

Решение владельца: убрать из интерфейса и кода (`server/src/infrastructure/
iflytek.ts`, `azure-speech.ts`, маршрут `/api/speech`) или оставить
скрытыми. Сейчас `/api/speech/audio` при заданном `AZURE_SPEECH_KEY` даёт
любому вошедшему 300 синтезов за 10 минут за счёт сайта без учёта — если
оставлять, то через K13.
