# Открытие сайта для других пользователей — план работ

Аудит от 2026-11-04 (коммит `7452528`). Сейчас сайт — приложение для одного
человека: любой может зарегистрироваться, но лимиты, квоты, хранение данных и
устройства рассчитаны на одного ученика. Ниже — что найдено и что сделать, по
фазам. Фаза 0 обязательна до того, как давать ссылку кому-либо.

## Как с этим работать агенту

1. Возьми **одну** задачу (или одну фазу, если так сказали). Не трогай чужие.
2. Перед работой прочитай `CLAUDE.md`, `docs/guidelines.md`; для любого экрана —
   скилл `hanzi-design`. Читай только документы своей фичи (таблица в `CLAUDE.md`).
3. Проверка: `npm test` и `npm run vercel-build`. Сервер тестируй только с
   `HANZI_DB=.data/<name>.db` — без него dev-сервер ходит в **боевую** базу.
4. Когда задача сделана и проверена — поставь `[x]`, допиши строку в
   «Журнал» внизу (дата, ID, коммит, что осталось) и закоммить этот файл вместе
   с кодом (протокол коммита из `CLAUDE.md`, только явные пути).
5. Сделано частично — оставь `[ ]`, допиши `— частично: …` в конце пункта и
   строку в журнал.
6. Пункт помечен **(владелец)** — это делает человек в панели сервиса, агент
   только напоминает и пишет инструкцию.
7. **Никаких платных сервисов сверх Vercel и уже подключённой базы.** Защита
   от злоупотреблений — в коде (приглашения, лимиты и квоты в базе,
   выключатели). Нельзя добавлять Upstash, Sentry, Plausible, Resend,
   платные функции Vercel Firewall и т.п. Нужен новый сервис — сначала
   спросить владельца.

Важность: **К** — критично, **В** — высокая, **С** — средняя, **Н** — низкая.

### Платные API

- [ ] **S3 (К) Azure TTS: квота, общий кэш, выключатель.** `/api/speech/audio`
  (`server/src/http/routes/speech.ts`) тратит серверный ключ Azure для любого

  выключатель; (4) при исчерпании — понятная ошибка, приложение переходит на
  системный голос.
- [ ] **S3b (В) (владелец) Бюджет Azure.** Ресурс Speech на F0 или бюджет с

## Фаза 2 — адреса: перезагрузка не сбрасывает экран

Правило (записать в `docs/guidelines.md`):
- **В адресе** — то, что отвечает на вопрос «где я»: какой объект (путь),
  вкладка, шаг, строка, фильтр, поиск (query), место на странице (hash).
  Переходы внутри одного экрана — `replace`, чтобы «Назад» не листал каждую
  строку.
- **В localStorage (по пользователю, S5)** — привычки устройства: скорость,
  голос, вид списка. Не больше нескольких КБ на ключ.
- **В рабочем месте на сервере** — учебные данные: прогресс, попытки, наборы.
- **Нигде** — открытые меню, наведение, временные анимации.

Задачи (каждую проверить: открыть экран, дойти до состояния, перезагрузить —
то же место; плюс открыть ссылку на другом устройстве):

- [ ] **U0 Проба перезагрузки.** Скрипт `scripts/reload-probe.mjs` (Playwright,
  Chromium и WebKit): для списка адресов открыть, выполнить действия,
  перезагрузить, сравнить заголовок и активную вкладку. Сначала прогнать — он
  покажет точный список того, что сбрасывается; дополнить пункты ниже.
- [ ] **U1 Текст: часть страницы.** Текущая часть (Read / Words / Grammar /
  Copy out / Dictation…) берётся из прокрутки (`useCurrentPart`,
  `src/features/reader/ReaderPage.tsx:451`); после перезагрузки — снова верх.
  Писать `#part-<id>` через `history.replaceState`, при загрузке прокручивать
  к нему (после того как блоки получили размер — без сдвига вёрстки).
- [ ] **U2 Copy out и Dictation: место.** Номер строки/предложения —
  `?line=N` (как в Speak), показан ли текст — уже в localStorage, оставить.
- [ ] **U3 Speak: у каждой фразы свой адрес.** Сейчас
  `/speaking/say/:source?line=N` по **номеру** строки: если текст поправили,
  номер указывает на другую фразу. Наборы «ещё раз» и «слабые строки»
  (`again:…`, `hanzi.speak.sets`) живут только в localStorage — на другом
  устройстве или после очистки ссылка уводит на главную Speak
  (`SpeakSay`, `src/features/speak/SpeakPage.tsx:258`).
  Сделать: (1) стабильный id фразы (`hash(zh)` короткий) — адрес
  `/speaking/say/:source/:phraseId`, старый `?line=` переадресуется;
  (2) наборы хранить в рабочем месте (`settings`/`speakSets`, не больше 20

- [ ] **U4 Рассказчики** (`/speaking/voices`, `NarratorsPage.tsx:42,493,501`):

## Фаза 3 — SEO

Сейчас всё за входом: любая ссылка ведёт на `/login`, поисковик видит пустой
`<div id="root">`. В `index.html` описание старое («printable worksheets»), нет
`robots.txt`, `sitemap.xml`, Open Graph; на любой адрес отвечает `index.html`
с кодом 200 — для поисковика нет настоящих 404. Индексировать стоит только
открытые страницы; учебные экраны — закрыть.

- [ ] **SEO1 Открытая главная `/`** для того, кто не вошёл: что это, для кого
  (HSK 1–2, iPad/iPhone), три-четыре экрана, кнопки «Войти» и «Есть
  приглашение». Статический HTML, отрендеренный при сборке (prerender через
